# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Go REST API (Gin) that serves Pokémon data from a MySQL database. The database contents are produced by a separate project, **pokedata** (also built in Jenkins); this repo only reads from it. Code comments and user-facing strings are mostly in Spanish.

## Commands

Toolchain is pinned with mise (`mise.toml`: Go 1.27.2, gopls, golangci-lint, sqlc). Run `mise install` to get them.

```bash
go build ./...                  # build
go run ./main.go                # run locally (needs PORT and DB_* env vars, see .env.example)
golangci-lint run               # lint
sqlc generate                   # regenerate queries/ after editing query.sql or schema.sql
docker build -t poketeamcalculator .
docker compose up --build       # runs the app only, using .env
```

There are no tests yet. When added, run a single one with `go test ./path/to/pkg -run TestName`.

## Architecture

- `main.go` — calls `database.Initialize()`, then registers Gin routes under `/api/v1/` and listens on `:$PORT`.
- `database/` — builds the MySQL DSN from env vars (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_TLS`), retries the connection for up to ~60s, and sets a global `DB` plus a status (`starting`/`ok`/`error`). The DB counts as populated only if the view `v_gimnasios` exists, because pokedata creates the views last. An unpopulated DB is logged, not fatal.
- `queries/` — **generated by sqlc, do not edit by hand.** Source of truth is `query.sql` (named queries) plus `schema.sql`. `sqlc.yaml` maps nullable `int`/`varchar`/`text` columns to `*int32`/`*string` and emits snake_case JSON tags, so the generated row structs are returned directly as JSON.
- `endpoints/<resource>/` — one package per resource, split into `controller.go` (Gin handlers), `services.go` (business logic such as pagination, fixed page size 20) and `struct.go` (response DTOs). Handlers get a repository via `queries.New(database.GetDatabase())`.
- `structs/` — shared DTOs (e.g. gym types) that no endpoint uses yet.
- `schema.sql` — generated from pokedata (`pokedata/cmd/pokedata-gen/sql/{schema,views}_mysql.sql`). Don't edit it by hand. Regenerate it from pokedata when that schema changes, then run `sqlc generate`.

## CI / Deployment

- **Jenkinsfile**: checkout → `sonar-scanner` (SonarQube server `SonarQube`, project key in `sonar-project.properties`) → `docker build` and push to `ghcr.io/dsaub/poketeamcalculator:latest` using the `github-pat` credential.
- **GitHub Actions** (`.github/workflows/docker-trivy.yml`): on pushes to `main`/`latest` and on PRs, builds the image and runs a Trivy scan. Any finding (any severity) opens a GitHub issue and fails the job.
- **Dockerfile**: multi-stage. The `ubuntu` stage only supplies an `/etc/passwd` with a `nonroot` user, the `golang:alpine` stage builds a static binary (`CGO_ENABLED=0`), and the final image is `scratch` running as `nonroot`.
- `docker-compose.yaml` defines only the `app` service. `.env.example` expects a `db` host that compose does not define, so MySQL must be provided separately.
